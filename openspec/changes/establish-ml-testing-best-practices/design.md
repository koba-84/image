## Context

現状のテストは一般的な機能確認が中心で、画像編集ML特有の「再現性・品質回帰・安全性」の観点が仕様として十分に固定されていない。  
本変更では OpenSpec でテスト要件を明示し、`tests/` と CI の実装方針を先に固定する。  
対象データフローは `入力画像 → 前処理 → 生成/編集推論 → 後処理 → 保存` であり、各段階での検証責務を分離する。

## Goals / Non-Goals

**Goals:**
- 画像編集MLプロジェクト向けのテスト階層（unit/integration/regression）を仕様化する。
- 再現性要件（seed、モデルバージョン、プロンプト、推論パラメータ、環境）を必須化する。
- 品質・性能・安全性の最低基準を測定可能な受け入れ条件として定義する。
- 失敗時の扱い（リトライ可否、ログ要件、中断条件）をテスト運用として定義する。

**Non-Goals:**
- 新しい生成/編集モデルの導入や再学習。
- 既存推論アルゴリズムの最適化。
- 既存CI基盤の全面的な再設計。

## Decisions

1. **テストを 3 層に分割する（unit/integration/regression）**  
   - Rationale: 変更検知コストを抑えつつ、モデル回帰を段階的に検出できる。  
   - Alternative: すべて統合テストに集約 → 実行時間増大と原因切り分け困難のため不採用。

2. **再現性メタデータを必須記録にする**  
   - Rationale: seed 固定だけでは再現不能なケースがあるため、モデルID・推論パラメータ・実行環境も必要。  
   - Alternative: seed のみ記録 → GPU/ライブラリ差分で同一結果保証が弱いため不採用。

3. **画像回帰は複数指標で評価する**  
   - Rationale: 単一指標は誤検知/見逃しが多いため、ピクセル差分と知覚品質系の併用を前提化する。  
   - Alternative: 人手目視のみ → スケールせず自動化できないため不採用。

4. **CI は軽量必須スイートと重い検証スイートを分離する**  
   - Rationale: PRゲートの速度と品質担保を両立する。  
   - Alternative: 全テストをPRごとに実行 → 待ち時間増加により開発速度を阻害するため不採用。

## Risks / Trade-offs

- **[Risk]** 回帰しきい値が厳しすぎて flaky failure が増える  
  **→ Mitigation:** 初期は監視モードで分布を収集し、閾値を調整してから必須化する。
- **[Risk]** ゴールデン画像更新が恣意的になる  
  **→ Mitigation:** 更新時に根拠（モデル変更/仕様変更）と比較結果の記録を必須化する。
- **[Risk]** 決定論モードで実行時間が増える  
  **→ Mitigation:** 再現性必須ケースを限定し、開発用スイートと完全検証スイートを分離する。

## Migration Plan

1. `ml-testing-practices` spec を追加し、受け入れ条件を確定する。  
2. 既存 `tests/` を分類し、不足するケース（回帰・安全性）を追加する。  
3. pytest マーカーと CI ジョブを整理し、PR必須スイートを固定する。  
4. 失敗時ログ形式と再実行手順を文書化する。  
5. 既存テストが不安定な場合は一時的に quarantined 扱いで原因を特定後に復帰させる。

Rollback:
- 新規マーカー・新規ジョブを段階的に無効化できるようにし、致命的な不安定化時は必須ゲートを旧構成に戻す。
